## 결정과 이유

- **카탈로그를 데이터로 두었습니다.** 원문의 핵심 요구가 「항목은 제가 추후 임의로 넣을 수 있어야 함」이므로, 항목·선택지를 코드가 아닌 저장 데이터로 관리하고 화면에서 추가·수정합니다. 입력 화면·거르기·분석·Excel 머리행이 모두 카탈로그에서 만들어집니다.
- **레코드에는 선택지 이름이 아니라 선택지 id 를 저장합니다.** 선택지 이름을 고치면(예: 「CAN type」→「CAN」) 이미 입력한 레코드에도 새 이름이 보여, 같은 선택지가 둘로 갈리지 않습니다.
- **지우기 대신 숨기기**입니다(기획서 5장). 숨긴 항목·선택지는 새 입력에서 빠지지만, 쓰인 기록은 집계에 「(숨김)」으로 남습니다.
- **초기 선택지는 원문에 나온 것만 넣었습니다.** check engine lamp(CAN type / HW type), 장비 유형(굴삭기·지게차·발전기), 지역(한국·유럽·미국)입니다. ATS type·CAN SA·Pedal type·starter control type 은 선택지가 원문에 없어 비워 두었고, 화면에 「선택지가 아직 없습니다」로 안내합니다.
- **표기 흔들림은 가져오기에서 막습니다.** 대소문자·띄어쓰기·하이픈만 다른 값(「hw type」)은 기존 선택지로 자동 연결하고, 그 밖의 모르는 값(「CAN」)은 「새 선택지로 추가 / 기존 선택지로 연결 / 비워 둠」 중에서 고르게 했습니다. 카탈로그에 없는 열은 「새 옵션 항목으로 추가」로 항목째 만들 수 있습니다. 열 연결은 저장해 두고 다음에 같은 열 이름이 오면 자동으로 씁니다.
- **비율의 분모**: 사용 빈도는 대상 레코드 전체(미입력 포함), 피벗은 행(기준값) 안의 건수입니다. 「가장 많이 쓰는 선택지」는 미입력을 빼고 세며, 건수가 같으면 함께 적습니다.
- **차트는 라이브러리 없이 HTML 막대**로 그렸습니다. 외부 CDN 을 쓰지 않아 오프라인·폐쇄망에서도 그대로 보입니다. 색은 선택지의 카탈로그 순서에 고정(8색, 색각 이상 구분 검사 통과)해 거르기를 바꿔도 같은 선택지는 같은 색이고, 미입력은 회색입니다. 색만으로 구분하지 않도록 범례·표·마우스 올림 설명을 함께 둡니다.
- **백업 파일(JSON)을 기본 보관 수단**으로 두었습니다. 브라우저 저장소는 브라우저 데이터를 지우면 사라지기 때문입니다(기획서 7장). 숨김 상태까지 그대로 옮기려면 백업 파일을, 다른 사람과 표로 나누려면 Excel 내보내기를 씁니다.
